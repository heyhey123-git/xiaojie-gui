[B][SIZE=4]A menu framework for Skript.[/SIZE][/B]
Describe a menu once — its layout, its pages, its icons — then fill it and answer clicks with Skript
syntax instead of building inventories by hand.[/CENTER]

[HR][/HR]

[B]xiaojie-gui[/B] adds inventory menus to Skript as ordinary Skript elements. A script describes a menu once —
the container it opens, the layout of its slots, the pages it can show and the items that go in them — and
from then on opening it, filling it, turning its pages and reacting to a click are effects, sections,
conditions and expressions. There is no Java to write and nothing to configure first.

The layout is a picture of the menu: one string per row, one character per slot, and
[ICODE]map key "A" to icon diamond named "&bDiamond"[/ICODE] says what the character [ICODE]A[/ICODE] is.
Each player gets their own window, so two people can look at the same menu from different pages with
different contents, and a click arrives as an event carrying the slot, the icon, the click type, which
number key was pressed, and — when the player swept over several slots — every slot the drag reached.

Two modes decide what is behind the window. [ICODE]phantom[/ICODE] is a window the addon draws itself with
packets: the items in it are fixed and cannot be taken out, which is what a row of buttons wants.
[ICODE]static[/ICODE] is a real inventory the server creates: items move, swap and drop the way they do in a
chest, which is what a vault wants. A menu that does not name a mode is [ICODE]phantom[/ICODE].

What it deliberately is not: it registers no commands and no permission nodes, so every entry point is a
script of your own; it writes no config file, so there is no setup step before a menu works; and it is not a
menu format loaded from a file — a menu is built by Skript code as the script loads, and building it again in
[ICODE]on load[/ICODE] is the normal shape. Everything it shows a player is a container window; there is no
text input inside one, and nothing is drawn outside it.

[B][SIZE=3]Requirements[/SIZE][/B]
[LIST]
[*][B]Paper[/B] 26.2 or newer, or a compatible fork. [ICODE]plugin.yml[/ICODE] declares
[ICODE]api-version: 26.2[/ICODE], so an older server refuses to load the plugin outright instead of loading it
and then failing with strange errors at runtime.
[*][B]Java[/B] 25 — what Paper 26.2 itself requires.
[*][B]Skript[/B] 2.16.2 or newer. That is the release that added Paper 26.2 support and the version this build
compiles against and runs its tests on, so on anything older the two floors are really one: an older Skript
cannot run on the server this build targets. The addon registers its syntax through Skript's addon API rather
than through the deprecated static calls.
[*][B]PacketEvents[/B] 2.13.0 or newer — [B]a required dependency[/B], not an optional one.
[ICODE]plugin.yml[/ICODE] lists [ICODE]packetevents[/ICODE] under [ICODE]depend[/ICODE], so without it the
plugin does not enable at all.
[*][B]SkBee[/B] is optional, and only needed to use a text component as a menu title. Without it a title is
plain text with the usual [ICODE]&[/ICODE] colour codes; a value that is not a string is refused with a message
that says what it could not convert; where the syntax lets the title be left out, an unreadable value is
ignored and the current title stays.
[*][B]No commands and no permissions.[/B] Everything is a Skript element, so there is nothing to grant and
nothing to type into chat.
[*][B]No config file and no data folder.[/B] There are no options to set and no state to keep, so nothing is
written under [ICODE]plugins/xiaojie-gui/[/ICODE]. The one path the plugin reads there is
[ICODE]lang/[/ICODE], and only if a server owner chooses to drop a language file into it; the plugin never
creates it.
[/LIST]

[B][SIZE=3]Install[/SIZE][/B]
[LIST=1]
[*]Download [ICODE]xiaojiegui-<version>.jar[/ICODE] from the releases page linked at the bottom.
[*]Put it in the server's [ICODE]plugins/[/ICODE] folder, next to Skript and PacketEvents.
[*]Restart the server, write the menu into a script, and [ICODE]/sk reload[/ICODE] it.
[/LIST]
The jar bundles Kotlin's standard library and relocates it under the plugin's own package
([ICODE]io.github.heyhey123.xiaojiegui.libs.*[/ICODE]), so it cannot collide with another plugin's copy of the
same classes, and it is built with minimization, so only the classes it really uses are inside. Nothing is
obfuscated: the source is public and readable, and the documentation and the tests live in the same
repository, as the resource standards require.

[B][SIZE=3]A script looks like this[/SIZE][/B]
[CODE]on load:
    build a menu {_menu}:
        inventory type: chest inventory
        title: "&6Shop"
        layout: "#########", "#A     B#", "#   C   #", "#########"
        id: "shop"
        click delay: 100
        edit:
            insert page 2 with layout "#########" and "#D     B#" and "#   E   #" and "#########" with title "&6Page two"
            map key "A" to icon diamond named "&bDiamond" for {_menu} and when clicked:
                send "&aYou picked the diamond in slot %the clicked slot%." to player
            map key "D" to icon emerald named "&aEmerald" for {_menu} and when clicked:
                send "&aYou picked the emerald in slot %the clicked slot%." to player
            map key "B" to icon clock named "&eClose" for {_menu} and when clicked:
                close the menu for player
            map key "C" to icon arrow named "&eNext page" for {_menu} and when clicked:
                turn to page 2 for player with new title "&6Page two"
            map key "E" to icon arrow named "&ePrevious page" for {_menu} and when clicked:
                turn to page 1 for player with new title "&6Page one"

command /shop:
    trigger:
        set {_menu} to the menu with id "shop"
        open menu {_menu} for player[/CODE]
The first line builds the menu and stores it in [ICODE]{_menu}[/ICODE], and everything indented under it
belongs to it: page 2 is added, then each character of a layout is tied to an item and, where a
[ICODE]when clicked[/ICODE] section follows, to the code a click on it runs. The character [ICODE]B[/ICODE]
appears in both layouts, so it is the close button on whichever page it is drawn. The command finds the menu
by its id and opens it for whoever typed it.

[B][SIZE=3]Features[/SIZE][/B]
[LIST]
[*][B]A layout is a picture of the menu.[/B] One string per row, one character per slot, starting at the top
left and reading left to right; a space is a slot too, it simply has no key. [ICODE]map key[/ICODE] ties a
character to an item and [ICODE]override slot[/ICODE] puts one item in one numbered slot. A character is only a
name, so the layout decides which slots exist, never what they look like.
[*][B]Pages are something you add, not something you manage.[/B] The layout given when the menu is created is
always page 1, and most menus never leave it. [ICODE]insert page[/ICODE] adds another one, at the end or at a
position; page numbers start at 1; and [ICODE]turn to page[/ICODE] moves one viewer without touching anybody
else's window.
[*][B]One menu, as many windows as players.[/B] The menu is the shared definition — layouts, pages, icons; a
window is what one player sees, with their own page and their own title. One person's slot is changed with
[ICODE]set icon in slot 5 of the menu session of player to X[/ICODE], while [ICODE]override slot[/ICODE]
changes the menu for everyone looking at it.
[*][B]A click is an event with all of its detail.[/B] [ICODE]on menu interact[/ICODE] runs once per interaction
and carries [ICODE]the clicked slot[/ICODE], [ICODE]the clicked icon[/ICODE], [ICODE]the click type[/ICODE] in
Skript's own words, and [ICODE]the pressed number key[/ICODE] as 1 to 9, which is the one thing Skript's click
type cannot tell apart. [ICODE]cancel event[/ICODE] refuses the interaction.
[*][B]A drag is one interaction, not one per slot.[/B] A sweep across several slots fires the event once, with
every slot it reached in [ICODE]the dragged slots[/ICODE] and — in a [ICODE]static[/ICODE] menu, the only one
with a real cursor — the carried stack in [ICODE]the cursor item[/ICODE]. A one-slot drag is delivered by the
game itself as an ordinary click, so a script never has to tell the two apart, and cancelling refuses the whole
sweep because the protocol cannot apply half of one.
[*][B]Two modes, one script.[/B] [ICODE]phantom[/ICODE] draws the window with packets and keeps its contents
fixed, so nothing in it can be carried away; [ICODE]static[/ICODE] is a real server inventory whose items the
player moves, swaps and drops as usual. The same menu code works in either mode, so changing the mode is not a
rewrite.
[*][B]A page can be a list.[/B] Map a list of items to one key and those slots become the page's result cells.
[ICODE]set the menu list of the menu session of player to {results::*}[/ICODE] fills them for one player in a
single call — extra items dropped, cells with nothing left cleared, the window updated once instead of once per
cell — and [ICODE]the menu list index[/ICODE] says which result was clicked.
[*][B]Slots can belong to the menu.[/B] [ICODE]with locked icons[/ICODE] makes the slots a layout gives an icon
to the menu's own: no click, shift click, number key, offhand swap, drop or double-click collect can take from
them or put anything in. A [ICODE]phantom[/ICODE] window cannot move anything anyway, so this is what a
[ICODE]static[/ICODE] menu needs. The slots the layout leaves empty stay the player's, which is how a shop
(icons) and a backpack (empty slots) are the same mechanism, and [ICODE]lock the icons of %menu%[/ICODE] flips
the switch while the server runs.
[*][B]The container types are Skript's own.[/B] A chest is sized by its layout, and the fixed windows are there
too: hopper, dropper, dispenser, barrel, ender chest, shulker box, anvil, beacon, furnace, smoker, blast
furnace, grindstone, smithing table, loom, cartography table, brewing stand, lectern, stonecutter, enchanting
table, workbench, crafter and the merchant window. A slot count is the number of slots the client really draws
for that window, and a container the client has no window for is refused rather than approximated.
[*][B]A callback can be defined once and reused.[/B] [ICODE]define button "my_button"[/ICODE] gives an icon and
a click body a name, and any menu can map that name into its layout:
[ICODE]map key "A" to button "my_button"[/ICODE]; [ICODE]all buttons[/ICODE] lists those names. A callback can
also be attached to a slot on its own with [ICODE]when slot 4 is clicked[/ICODE], even when nothing is drawn in
that slot.
[/LIST]

[B][SIZE=3]Everything it adds[/SIZE][/B]
Square brackets mark what may be left out, the hyphen in [ICODE]%-number%[/ICODE] marks a slot that may be
dropped whole, and a vertical bar inside parentheses is a choice of words. The patterns are written the way a
script writes them: the tags the addon uses internally to tell a text title from a component title are not part
of what you type. Everything the addon registers is listed below — 13 effects, 8 sections, 3 conditions and 34
expressions — together with the four events, [ICODE]on menu open[/ICODE], [ICODE]on menu interact[/ICODE],
[ICODE]on page turn[/ICODE] and [ICODE]on menu close[/ICODE], which are described in the documentation.

[B]Effects[/B] — a statement written on one line, with no body
[CODE]Clear Session:
    clear [the] [menu] [(session|window)] %menusession% [and refresh]

Close Menu:
    (close|close down|shut) [the] (menu|gui) (for|to) %player%

Close Menu Session:
    close [the] [menu] [(session|window)] %menusession%

Destroy Menu:
    destroy [the] menu %menu%
    destroy [the] menu with id %string%

Hide Player Inventory:
    hide player inventory of %menu%
    show player inventory of %menu%

Insert Page:
    insert page [%-numbers%] [to %-menu%] [with layout %-strings%] [with player layout %-strings%] [with [new] title %-string%]
    insert page [%-numbers%] [to %-menu%] [with layout %-strings%] [with player layout %-strings%] [with [new] title %-object%]

Lock Icons:
    lock [the] icons of %menu%
    unlock [the] icons of %menu%

Open Menu:
    (open|show) [the] (menu|gui) [%-menu%] (for|to) %player% [and (turn to|go to|on) page %-number%]

Refresh Menu Session:
    refresh [the slot %-number% in] [the] [menu] [(session|window)] %menusession%

Set Menu List:
    set [the] menu list of %menusession% to %itemstacks%

Turn Page:
    turn to page %number% for %player%
    turn to page %number% for %player% [with [new] title %-string%]
    turn to page %number% for %player% [with [new] title %-object%]

Update Menu Session Title:
    update title of [the] [menu] [(session|window)] %menusession% to %-string% [(and refresh)]
    update title of [the] [menu] [(session|window)] %menusession% to %-object% [(and refresh)]

Update Page Title:
    update title [of page %-number%] [in %-menu%] to %-string% [(and refresh)]
    update title [of page %-number%] [in %-menu%] to %-object% [(and refresh)][/CODE]
[LIST]
[*][B]Clear Session[/B] empties the contents of a player's window without closing it. Adding
[ICODE]and refresh[/ICODE] pushes the emptied window to that player at once.
[*][B]Close Menu[/B] closes the window of a player who has one open. A player with nothing open gets a readable
one-line error rather than silence.
[*][B]Close Menu Session[/B] is the same operation addressed by the window itself instead of by the player.
[*][B]Destroy Menu[/B] throws a menu away, by value or by id. Anyone looking at it is closed out, a destroyed
menu cannot be opened or changed again, and destroying one twice does nothing.
[*][B]Hide Player Inventory[/B] hides or shows the half of the window below the container, in a
[ICODE]phantom[/ICODE] menu. A [ICODE]static[/ICODE] window always shows the player's own inventory, so there
the keyword does nothing, and a static menu created with it gets a line in the console saying so. Showing it is
refused, with a line saying so, for a menu whose page lays those rows out: those rows are the page's own space
there.
[*][B]Insert Page[/B] adds a page to a menu — at the end, or at a position — with its own layout, player layout
and title. The two title patterns are why a plain text title and a SkBee component title are both accepted.
[*][B]Lock Icons[/B] turns the "the icon slots are the menu's own" switch on or off. It changes what happens to
the next interaction, so nothing on screen changes because of it.
[*][B]Open Menu[/B] opens a menu for a player, optionally straight onto one page. With the menu left out it is
the menu the current event is about.
[*][B]Refresh Menu Session[/B] resends a window's contents, or a single slot of it. It does nothing in
[ICODE]static[/ICODE] mode, where the client keeps itself in step with the real inventory.
[*][B]Set Menu List[/B] fills the list slots of one player's window from a list of items, in layout order. The
whole window is refreshed once, which is what makes a page of results one call instead of one per cell.
[*][B]Turn Page[/B] moves a player to another page of the menu they have open, optionally with a title for that
one display. The page's own title is not changed by it.
[*][B]Update Menu Session Title[/B] retitles one player's window; [ICODE]and refresh[/ICODE] shows the new title
immediately instead of at the next refresh.
[*][B]Update Page Title[/B] retitles a page of a menu. Only the players looking at that page are told, and
[ICODE]and refresh[/ICODE] is what tells them now.
[/LIST]

[B]Sections[/B] — a body, and a colon when written in a script
[CODE]Build Menu:
    build [a] menu [%-object%]

Build and Insert Page:
    insert page [%-number%] into menu [%-menu%]

Create Menu:
    create [a] [phantom|static] menu with %inventorytype% titled %-string% with layout %strings% [with player layout %-strings%] [with id %-string%] [with page %-number%] [with %-number% ms click delay] [(with|without) hide player inventory] [(with|without) locked icons]
    create [a] [phantom|static] menu with %inventorytype% titled %-object% with layout %strings% [with player layout %-strings%] [with id %-string%] [with page %-number%] [with %-number% ms click delay] [(with|without) hide player inventory] [(with|without) locked icons]

Define Button:
    define [a] button %string%

Edit Menu:
    (edit|change) [the] [(menu|gui)] %menu%

Map Key to Icon:
    map key %string% to ((icon|item)[s] %-itemstacks%|button %-string%) [for [(menu|gui)] %-menu%] [on page[s] %-numbers%][(and (refresh|update))] [(and when clicked)]

Override Slot:
    (override|set) slot %numbers% [in page %-numbers%] to (%-itemstack%|button %-string%) for [the] [(menu|gui)] %-menu% [((and|with) (refresh|update))] [(and when (clicked|interacted|pressed))]

Set Slot Callback:
    (when|on) slot %numbers% [in page [(number|index)] %-numbers%] [of [(menu|gui)] %-menu%] [is] (clicked|interacted|pressed)[/CODE]
[LIST]
[*][B]Build Menu[/B] builds a menu from [ICODE]key: value[/ICODE] entries and stores it in the variable written
after [ICODE]build a menu[/ICODE]. Its own [ICODE]edit:[/ICODE] section holds the contents and the behaviour.
[*][B]Build and Insert Page[/B] adds a page to a menu from [ICODE]layout:[/ICODE],
[ICODE]player layout:[/ICODE] and [ICODE]title:[/ICODE] entries. All three are optional, and a page without a
layout inherits the menu's default layout.
[*][B]Create Menu[/B] creates a menu from one long first line, with the contents in the section body: everything
indented under it belongs to the menu. [ICODE]with id[/ICODE] names it, and an id that already exists destroys
the old menu first, which is why rebuilding a menu in [ICODE]on load[/ICODE] is safe.
[*][B]Define Button[/B] gives an icon and a click body a name that any menu can map. The [ICODE]icon:[/ICODE]
and [ICODE]when clicked:[/ICODE] entries are both required, and defining the same id again overwrites the old
one.
[*][B]Edit Menu[/B] changes no property by itself: it gives the section body a current menu, so
[ICODE]insert page[/ICODE] and the like inside it do not have to name the menu.
[*][B]Map Key to Icon[/B] ties a layout character to one item, several items, or a button. Without
[ICODE]on page[/ICODE] it applies to every page, including pages added later; without [ICODE]for[/ICODE] it uses
the menu of the current event.
[*][B]Override Slot[/B] puts one item, or a button, into numbered slots of a page. Without [ICODE]in page[/ICODE]
it uses the menu's default page, which is the value [ICODE]with page[/ICODE] set.
[*][B]Set Slot Callback[/B] attaches a click body to slots on its own, with no item needed. That is how an
invisible button — a slot that is empty but does something when clicked — is written.
[/LIST]

[B]Conditions[/B] — a test, written where a condition goes
[CODE]Icons Locked:
    [the] icons of %menu% (is|are) locked
    [the] icons of %menu% (isn't|is not|aren't|are not) locked

Menu is Destroyed:
    [the] [menu] %menu% (is|was) destroyed
    [the] [menu] %menu% (isn't|is not|wasn't|was not) destroyed

Player Inventory Hidden:
    player inventory of %menu% is hidden
    player inventory of %menu% (isn't|is not) hidden[/CODE]
[LIST]
[*][B]Icons Locked[/B] reads the same switch [ICODE]with locked icons[/ICODE] sets and
[ICODE]lock the icons of %menu%[/ICODE] can flip. Only the spellings in the pattern are accepted.
[*][B]Menu is Destroyed[/B] holds for a menu that was destroyed: by another creation with the same id, by
[ICODE]destroy[/ICODE], or by a script reload, which destroys every menu. A destroyed menu cannot be opened,
turned or changed.
[*][B]Player Inventory Hidden[/B] reads the [ICODE]hide player inventory[/ICODE] flag, which a player layout
sets as well in a [ICODE]phantom[/ICODE] menu. When the menu is not set the condition is false rather than an
error.
[/LIST]

    [the] slot[s] of [the] key %string% in [the] page %number% [of [the] [(menu|gui)] %-menu%][/CODE]
[LIST]
[*][B]Clicked Icon[/B] is the item in the slot the player clicked, in [ICODE]on menu interact[/ICODE];
[ICODE]the icon[/ICODE] is the same value under its older name.
[*][B]Clicked Slot[/B] is the number of the slot the player clicked, counting from 0 at the container's top
left. For a drag it is the first slot the sweep reached in a [ICODE]phantom[/ICODE] menu and the lowest slot
the sweep touched in a [ICODE]static[/ICODE] one.
[*][B]Cursor Item[/B] is the stack the player was holding. It has a value in [ICODE]static[/ICODE] mode; in
[ICODE]phantom[/ICODE] mode the window is the server's own and there is no real cursor, so it is nothing.
[*][B]Default Layout[/B] is the layout a new page inherits when it is added without one. It can be read, set,
added to, removed from and reset like any other property.
[*][B]Default Page[/B] is which page [ICODE]open menu[/ICODE] shows first. It never changes how many pages
exist, and a value below 1 is clamped to 1.
[*][B]Default Title[/B] is the title new pages are given, which is the value [ICODE]titled …[/ICODE] set. It is
a string, or a component on a server with SkBee.
[*][B]Dragged Slots[/B] is every slot a sweep reached, in ascending order in a [ICODE]static[/ICODE] menu and
in the order the drag reached them in a [ICODE]phantom[/ICODE] one. It is empty for a click and also for a
one-slot drag, which the game delivers as an ordinary click.
[*][B]Event Page[/B] is the page the event happened on; in [ICODE]on page turn[/ICODE] the future page is the
page being turned to. In [ICODE]on menu open[/ICODE] and [ICODE]on menu interact[/ICODE] there is no future
page, so it is nothing.
[*][B]Event Title[/B] is the title the page being turned to will have, in [ICODE]on page turn[/ICODE]. It can be
set there, and it applies to that one turn only.
[*][B]Get All Buttons[/B] is every button id that has been defined.
[*][B]Get All Menu IDs[/B] is every menu id that has been created. A menu built without an id is not in it.
[*][B]Get All Menus[/B] is every menu that has an id, as menu values.
[*][B]Get Menu by ID[/B] is the menu with the given id, or nothing when no menu has it.
[*][B]Key of Slot[/B] is which layout character a slot holds, in a page of a menu. It is nothing for a slot with
no key, and it can be set like a property.
[*][B]Menu Click Type[/B] is the click the player made, as Skript's own click type, written and compared with
the words [ICODE]on inventory click[/ICODE] uses. [ICODE]the event-clicktype[/ICODE] is the same value.
[*][B]Menu Contents[/B] is everything a window's container holds, in slot order, with the empty slots left out.
Only the container is read, in either mode: the rows below it are left out even where a [ICODE]phantom[/ICODE]
menu owns them.
[*][B]Menu Current Page[/B] is the page a player is on, read from their window.
[*][B]Menu ID[/B] is the id a menu was created with. A menu created without one has no id to read.
[*][B]Menu Inventory Type[/B] is the container type the menu was created with.
[*][B]Menu List Index[/B] is the 1-based position of the clicked slot in the page's list, and nothing when the
clicked slot is not one of the list slots. That is how one handler tells a button from a result.
[*][B]Menu Mode[/B] is [ICODE]phantom[/ICODE] or [ICODE]static[/ICODE] as ordinary text, so it compares with a
plain string.
[*][B]Menu Session Icon[/B] is the item in given slots of one player's window. It can be read, set for one slot
or several, and deleted, and setting pushes it to that player immediately.
[*][B]Menu Session Page[/B] is which page a window is on, read from the window itself.
[*][B]Menu Session Title[/B] is the title of one player's window; it can be read or set.
[*][B]Menu Session's Viewer[/B] is the player the window belongs to.
[*][B]Menu Viewers[/B] is the players currently looking at a menu. It is called [ICODE]menu viewers[/ICODE]
rather than [ICODE]viewers[/ICODE] because Skript 2.16 registers a property of its own under the shorter name
and answers it first; [ICODE]all players viewing %menu%[/ICODE] is the same value.
[*][B]Minimum Click Delay[/B] is the shortest gap between two clicks the menu accepts, in milliseconds. A click
that comes sooner is silently dropped.
[*][B]Occupied Slots[/B] is the slots of a window's container that hold something, in ascending order. Together
with the icon expression it is how a menu that keeps things in its free slots is saved and put back.
[*][B]Page Number[/B] is how many pages a menu has, not which page is showing.
[*][B]Page Title[/B] is the title of one page of a menu; it can be read or set.
[*][B]Player's Menu Window[/B] is the window a player has open, or nothing when they have none.
[ICODE]window[/ICODE] is the word to reach for, and [ICODE]session[/ICODE] means the same thing.
[*][B]Pressed Number Key[/B] is which number key was pressed in [ICODE]on menu interact[/ICODE], 1 to 9, and
nothing for every other click. Skript's click type reports all nine keys as one value, so this is what tells
them apart.
[*][B]Session's Menu[/B] is the menu a window belongs to.
[*][B]Slots of Key[/B] is the slot or slots a key occupies in a page of a menu, or nothing when the key is in
no slot there. [ICODE]Key of Slot[/ICODE] is the same relationship read the other way round.
[/LIST]

[B][SIZE=3]What is new in 2.0.0[/SIZE][/B]
[B]Added[/B]
[LIST]
[*][B]Menus for more container types.[/B] [ICODE]barrel[/ICODE], [ICODE]ender chest[/ICODE],
[ICODE]dispenser[/ICODE], [ICODE]enchanting table[/ICODE], [ICODE]cartography table[/ICODE] and
[ICODE]crafter[/ICODE] can be created. They used to report [ICODE]Unsupported inventory type[/ICODE], because
no layout existed for them; note that Skript's names for two of them are [ICODE]enchanting table inventory[/ICODE]
and [ICODE]cartography table inventory[/ICODE].
[*][B]Dragging is handled.[/B] A drag used to reach the addon only when it happened to touch exactly one slot,
which the game itself delivers as a click; a real sweep changed the window with [ICODE]on menu interact[/ICODE]
never running, so a shop could not refuse it and a backpack could not see it. One drag is now one interaction,
with every slot it reached in [ICODE]the dragged slots[/ICODE] and, in a [ICODE]static[/ICODE] menu, the carried
stack in [ICODE]the cursor item[/ICODE], and [ICODE]cancel event[/ICODE] refuses all of it at once.
[*][B]Locked icons.[/B] The slots a layout gives an icon to can be made the menu's own, so nothing can be taken
from them or put into them. It is a [ICODE]static[/ICODE] menu's switch — a [ICODE]phantom[/ICODE] window
cannot move anything anyway. The same switch can be flipped while the server runs with
[ICODE]lock the icons of %menu%[/ICODE] and [ICODE]unlock the icons of %menu%[/ICODE], and read back with the
condition.
[*][B]A page can be a list.[/B] Mapping a list of items to one key turns that key's slots into the page's result
cells, and [ICODE]set the menu list of %menusession% to %itemstacks%[/ICODE] fills them for one player at once.
[ICODE]the menu list index[/ICODE] then says which result was clicked, which is what makes an item browser a
layout plus one call plus one number.
[*][B][ICODE]player layout[/ICODE], and a window that can be read back.[/B] The layout of the rows below the
container is what [ICODE]player inventory layout[/ICODE] is called now, and in a [ICODE]phantom[/ICODE] menu
writing one hides the player's inventory, so that half belongs to the menu instead of quietly doing nothing; on
a [ICODE]static[/ICODE] menu it warns once and changes nothing. A window can be read back with
[ICODE]the occupied slots of %menusession%[/ICODE] and [ICODE]the menu contents of %menusession%[/ICODE], which
together with the icon expression is how a backpack is saved on close and put back on open.
[/LIST]
[B]Changed[/B]
[LIST]
[*][B]The requirements moved up.[/B] Paper 1.21.8 became Paper 26.2, Skript 2.13.1 became 2.16.2, PacketEvents
2.9.5 became 2.13.0 and Java 21 became Java 25. [ICODE]plugin.yml[/ICODE] declares [ICODE]api-version: 26.2[/ICODE],
so an older server refuses to load the plugin rather than loading it and failing later.
[*][B]The old [ICODE]gui[/ICODE] syntax is removed.[/B] [ICODE]create a gui …[/ICODE],
[ICODE]%players% (has|have) a gui [open][/ICODE] and [ICODE]the player's gui[/ICODE] came from the earlier
skript-gui addon: [ICODE]create gui[/ICODE] numbered pages from 0, so it crashed as soon as the inventory it was
given had an item in it. Use the menu syntax, [ICODE]the menu of the menu session of player[/ICODE],
[ICODE]if the menu session of player is set:[/ICODE], and [ICODE]create a static menu …[/ICODE] for what
[ICODE]removable items[/ICODE] used to mean.
[*][B][ICODE]the viewers of %menu%[/ICODE] is [ICODE]the menu viewers of %menu%[/ICODE] now.[/B] Skript 2.16
registers a [ICODE]viewer[s][/ICODE] property of its own over any object and registers it before this addon, so
the shorter form was answered by Skript and returned nothing. [ICODE]all players viewing %menu%[/ICODE] is
unchanged.
[*][B]A menu's mode is plain text.[/B] [ICODE]the mode of {_menu}[/ICODE] returns [ICODE]phantom[/ICODE] or
[ICODE]static[/ICODE], so [ICODE]if the mode of {_menu} is "phantom":[/ICODE] is an ordinary text comparison. The
old [ICODE]receptaclemode[/ICODE] type is gone with it, and so is a trap: bare [ICODE]phantom[/ICODE] used to be
compared against Minecraft's phantom entity and never matched.
[*][B]Page numbers start at 1 everywhere.[/B] [ICODE]page 0[/ICODE] no longer exists, and [ICODE]the page[/ICODE]
inside [ICODE]on menu interact[/ICODE] reports 1 for the first page instead of its 0-based position in the menu's
list. The layout a menu is created with is always page 1; [ICODE]with page N[/ICODE] only decides which page
[ICODE]open menu[/ICODE] shows first, where it used to stop any page from being created at all, so
[ICODE]create menu … with layout … with page 2[/ICODE] produced a menu that could not be opened.
[/LIST]
[B]Fixed[/B]
[LIST]
[*][B]Every title syntax used to crash.[/B] [ICODE]create menu … titled …[/ICODE],
[ICODE]insert page … with title …[/ICODE], [ICODE]update title …[/ICODE] and the rest threw an internal error
as soon as a script ran them, so a menu created that way was never actually created. A title is now simply the
value: text with the usual [ICODE]&[/ICODE] colour codes, or a component on a server with SkBee.
[*][B]A title written with one of the addon's internal tags is refused instead of rendered.[/B] Hand-writing the
tag that tells a text title from a component title used to make the whole text, tag included, the title; 2.0.0
reports it, because those tags belong to the addon's patterns and not to script syntax.
[*][B][ICODE]cancel event[/ICODE] works in [ICODE]on menu open[/ICODE] and [ICODE]on page turn[/ICODE].[/B] One of
the two ignored the argument and cancelled regardless, the other never cancelled, so a permission check in
[ICODE]on menu open[/ICODE] did not stop the window from appearing.
[*][B][ICODE]update title of page N[/ICODE] retitles only the players looking at page N.[/B] It used to retitle
the window of every viewer of the menu, so a player on another page kept seeing that page's title until they
turned a page.
[*][B]Opening a menu a player already has open goes to the page asked for.[/B] It used to fail with
[ICODE]already viewing this menu[/ICODE].
[*][B]The fixed-size layouts now count the slots the client really draws.[/B] [ICODE]workbench[/ICODE] has 10
rather than 9, [ICODE]beacon[/ICODE] 1 rather than 3, [ICODE]enchanting table[/ICODE] 2 rather than 3,
[ICODE]lectern[/ICODE] 1 rather than 2, [ICODE]smithing[/ICODE] 4 rather than 3 and [ICODE]cartography table[/ICODE]
3 rather than 4. A count that is off reports nothing and moves the player's inventory and every click by a few
slots, so a unit test now holds every layout to Bukkit's own size for its type.
[*][B][ICODE]crafting table inventory[/ICODE] is no longer a layout.[/B] No client menu draws that window, so it
came out as a crafting table whose 10 slots were mapped onto the addon's 5, and Bukkit refuses to create that
inventory at all. [ICODE]workbench inventory[/ICODE] is the crafting-table window.
[*][B]A [ICODE]static[/ICODE] merchant menu stops with a sentence instead of an exception.[/B] Merchant windows
come from the merchant API and only work in [ICODE]phantom[/ICODE] mode, and the error now names the type
instead of letting Bukkit's own exception out.
[*][B]A page turn clears only the slots the page being left owns.[/B] Clearing the whole window threw away
whatever the player had put in a slot the layout left empty, which made a paging backpack impossible.
[*][B]A player who leaves a [ICODE]static[/ICODE] menu leaves nothing behind.[/B] Quitting, dying or changing
world with one open used to keep their entry, and the items in it, in memory for as long as the server ran, one
per player.
[*][B]Static menus no longer send the whole window twice on every page turn[/B], and a menu the player closed is
not reopened by a title update that was still in flight.
[*][B]A click in the player's own half of a [ICODE]static[/ICODE] window is reported with the window slot the
client used.[/B] The old number was relative to that half, so it named a container slot the player never touched
and ran a callback for it.
[*][B]The click a script is told about is the click the player made.[/B] Reading the event's action as well as
its click type reported a drop in a slot as a click on the background and a click on the background as a drop.
[*][B]A failure that used to be a stack trace is now a sentence.[/B] A page number out of range, a menu that was
destroyed, and an expression used outside a menu event report something readable instead of throwing inside
Skript.
[*][B]Reloading scripts closes every menu first.[/B] A menu holds the callbacks of the script that built it, so
a menu that survived [ICODE]/sk reload[/ICODE] answered the next click with code that was no longer in any
script. The reloaded scripts build their menus again, as they do on start.
[/LIST]

[B][SIZE=3]Good to know[/SIZE][/B]
[LIST]
[*][B]A window already on screen cannot be retitled.[/B] The protocol has no "set the title": the only way a
title changes is a second open-window packet, so a title update re-opens the window on the next tick. Closing
the menu in that same tick is still final -- the late re-open is dropped once the window is closed -- so a
script can update a title and close in whichever order it reads best.
[*][B]The click cooldown drops clicks silently.[/B] When the gap between two clicks is smaller than
[ICODE]click delay[/ICODE], the event does not fire and the slot callbacks do not run, with no message at all.
The default is 50 milliseconds for [ICODE]create menu[/ICODE] and 5 milliseconds for [ICODE]build a menu[/ICODE],
so when a click seems to do nothing, this value is worth checking first.
[*][B]Creating a menu with an id that already exists destroys the old menu first.[/B] That is intended, and it is
why rebuilding a menu in [ICODE]on load[/ICODE] is safe: the old one is closed, no player is left stuck in a
window that no longer exists, and two menus with one id never coexist.
[*][B]A container type the addon cannot open is refused, not half-built.[/B] A type the client has no window for
is reported with a message naming it, and the menu is not created. Minecraft has no menu for a composter, a
chiseled bookshelf, a decorated pot, a shelf or a jukebox, so those cannot be supported at all.
[*][B]Reloading scripts destroys every menu.[/B] A script reload throws every player out of their window,
because a menu holds the callbacks of the script that built it. Building the menus again in [ICODE]on load[/ICODE]
is enough, and the addon sends the reloaded scripts on to do exactly that.
[*][B]The addon's own messages are English.[/B] It ships no translation of its own: the only language entry it
carries names its two types, for Skript's error messages, and a server owner may drop a file of their own into
[ICODE]plugins/xiaojie-gui/lang/[/ICODE]. That file is read by Skript, not by the client, so it is not the
server's chat language.
[/LIST]
